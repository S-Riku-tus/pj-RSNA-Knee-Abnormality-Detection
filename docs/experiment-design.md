# モデルと検証の設計

自作コードは、ラベルの取り込みから推論までを理解・変更できる工学的ベースライン。公開Notebookのスコア再現は別経路で行う。

10月4日時点で公開モデルの採点、e001の1 epoch、e002の5 epoch基準実験は完了。以下の実装説明は現行版で、追加実験の詳しい対照条件と分岐は [次の実験計画](research/next-experiments-20261004.md) を正本とする。事前学習・追加ログ・BN条件はまだ実装していない。

## ラベルを作る情報と推論入力

```text
学習用レポート → 公開ラベルまたは監査したラベル作成器 → weak_labels.csv
MRI → 共通DICOM前処理 → 2.5D画像窓 → 所見別Attention → 12出力
```

ラベルCSVは `StudyInstanceUID` と12の提出列を持つ。値は0〜1、欠損は空欄。出力順が異なる公開ラベルは列名を合わせて変換する。余分なIDは拒否し、欠損値はlossから除外する。`label-template` の空欄は準備用で、生成済みラベルではない。

`source_url, source_version, license, method, created_at, gold_used_for_tuning` をprovenance.jsonに記録してから `prepare` する。公開ソースのgold利用が不明なら、確認してから取り込む。初期版は外部LLM呼び出しや未検証の多言語キーワード抽出を実装していない。ラベル作成方法を変える場合、否定・疑い・重症度・言及なしを区別し、同じ意味の教師信号になるか監査する。

## 分割と評価

- `gold.csv`：公式ラベルが一つでもある検査を全て予約。学習から外し、checkpoint選択にも使わない。
- `weak.csv`：レポート由来の教師信号。5foldのうち指定foldを検証に使う。
- 同一レポートは空白を正規化しcasefoldしてグループ化。任意の `StudyInstanceUID,group_id` CSVを渡せば患者・施設・近重複等のグループを追加できる。連結したグループ全体を同じfoldにする。
- goldと同じグループのweak検査は学習対象から除外する。
- foldはseedとgroup hashから安定して生成。層化分割ではないため、GPU端末で各クラスの陽性・陰性数を確認する。
- 患者IDや施設の対応をまだ確認していない。標準分割だけで患者独立・施設独立とは主張できない。同一レポートの近似一致や画像近重複も追加監査する。

weak検証の選択指標はmasked BCE。soft labelを0.5で二値化して公式AUCと同一視しない。`evaluate` は0/1の観測ラベルだけでクラス別AUCを計算する。陽性・陰性の両方がないクラスは未定義にし、12クラス全てが定義された場合のみ `macro_auc_12` を返す。部分クラス平均は別の名前で出す。

goldは少数であり、繰り返し調整に使うと独立性が失われる。ラベル作成器が既にgoldを見ている場合も同じ。小さなAUC差だけで改善を断定しない。Public LBも繰り返し合わせ込まず、検証の異なる3指標を混同しない。

## MRI前処理

1. 最大3シリーズを選ぶ。液体強調・脂肪抑制を優先し、異なる断面を先に採る。公式メタデータの表記をGPU端末で確認する。
2. DICOMの方向ベクトルから面の法線を作り、位置を投影して並べる。全スライスに幾何情報がない場合だけInstanceNumberへfallbackする。部分的な欠損、同位置、混在方向は拒否する。
3. RescaleSlope/Intercept、MONOCHROME1の反転を処理し、シリーズごとの1〜99 percentileでuint8へ正規化する。
4. 192px正方形へ縮小し、シリーズ内の8中心点で隣接3枚を束ねる。異なるシリーズをまたいで3枚を作らない。
5. 不足するシリーズはmaskで除外する。全て読めない検査は停止し、定数予測で置き換えない。失敗・fallbackはprivateなcoverage.jsonに残す。
6. preprocessing fingerprintと元CSV hashをキャッシュに記録。画像前処理設定・元CSVが変わった場合、新しいキャッシュを作る。

初期版は画像の物理尺度を揃えず、正方形へのresizeで縦横比も変わる。再配向、左右の区別、両膝撮影、物理的crop、multiframe、localizer除外は実MRI監査後の改善項目。原画像とキャッシュを目視し、所見が残るかを確認してから本格学習する。公開CoAtNetの前処理とは互換でない。

## 画像モデルと計算

ランダム初期化ResNet18に12項目それぞれのAttention poolingを付ける。画像入力はuint8から[-1,1]へ変換。初期設定はbatch 1、4回の勾配蓄積、AMP、5epoch。これらはVRAMと速度をGPU端末で測るための出発点で、競争力や特定GPUへの適合を保証しない。自動の事前学習モデル取得はない。

checkpointはweak検証BCEが最小のepoch。保存内容はモデル、config、ラベル順、epoch、fold、前処理fingerprint。runには入力hash、ラベルprovenance、環境の版、GPU、履歴、予測を保存する。

## 実験の順番

1. 完了済みの公開モデル再現（p001、Public 0.924）とrandom基準（e001/e002）を保持する。以前の予定番号を実測run番号へ読み替えない。
2. epoch別weak評価、比較可能なeval loss、cache互換性検査を整える。人工入力の契約と少数trainへの適合で学習経路を確認する。
3. 同じ192px cacheでA（random＋現行正規化）、B（random＋ImageNet正規化）、C（事前学習＋Bと同じ正規化）を比較。選択規則を固定し、必要ならBN running statisticsの固定だけを別条件として調べる。
4. ラベルの大会利用条件を並行確認し、利用可能な自作モデルで早期にKaggleのオフライン推論・全体時間・採点を確認する。
5. 診断に応じてラベル版か入力を一要因ずつ変更。画像は224px全体像と同解像度の物理cropを分けて比較。256px以上の全件化は容量計測とUID分割・統合検査を先に整える。
6. 有望な条件だけ追加fold・seedへ広げ、別encoderは必要性が示された場合に追加する。新しい条件には新しいrun番号を割り当て、入力hash・環境・採用理由を残す。
7. 少数モデルの組み合わせは検証根拠と所要時間を確認後に検討し、10月20〜22日に最終候補を固定する。goldを係数合わせに使わない。

限られた期間では、採点済み候補を保持しながら不振の原因を切り分ける。epoch増加や大型モデルの全探索から始めない。
