2026年10月5日 JST。添付分析を、作業開始時のHEAD `ea27fbdc37f4b4119332bb83af22fce0b31b15bc`、実装、実験台帳、公開一次資料と照合した。原文は [添付分析](user-analysis-public-model-20261005.txt)。この計画を今後の優先順位の正本とし、10月4日までの自作モデル中心の次工程を更新する。

**目標は、採点済み公開モデルp001のPublic 0.924を保持し、それを置き換えるか補完する候補を作ること。最初の比較は公開重みによる推論で行う。** 自作ResNet18の全fold展開、50/100 epoch化、192px物理cropの全件作成は当面保留する。既存run・cache・checkpointは比較資料として保持する。

## 判断の根拠と限界

| 観測 | 言えること | まだ言えないこと |
|---|---|---|
| p001 Public 0.924 | 既に利用できる競技用の比較基準がある | 作者の最新コードと成功提出の全資産が同一である |
| r001 weak AUC 0.830249、API確認済みPublic 0.749 | weakで良くなった別系統が、公開基準を上回っていない | 差をcrop、解像度、モデル、教師のどれか一つで説明できる |
| B→Cの改善をfold 0/1で観測 | ImageNet初期化は自作方式内で有効だった | 膝MRIで学習済みの公開重みと同等の情報を得た |
| e008/e009の最良はepoch 8/9、終点は悪化 | 長期化だけを優先する根拠が弱い | 別設計の長期学習も全て無効である |
| fold 0 Synovitisは陽性100・陰性1 | macro12の一項目が単一陰性の順位に強く依存する | SynovitisだけがPublicとの差の原因である |

採点の確認段階、提出ID、Notebook版は [提出監査](../../experiments/submission-audit-20261005.json) に分けて記録する。添付報告値をAPI確認済み値へ無条件に置き換えない。weakとPublicは対象・正解・選択履歴が違い、0.830249−0.749を汎化ギャップの推定値として扱わない。Public同士の差も正解率差や統計的有意差ではない。

現在の`KneeMIL`はImageNet初期化ResNet18、最大3系列×8窓、全体192px、観測weakラベルと欠損maskを使う。公開CoAtNet重みは読み込んでいない。今回取得したp001成功版ソースでも140mm crop・336pxスタック・64枚・42窓を確認した。モデル型と384px入力はcheckpoint情報が優先されるfallback設定で、重み未取得の現状では実効値まで確定しない。複数条件が違う公開方式との比較は「方式全体の比較」であり、一要因の因果実験とは区別する。

## 競技用の採用と独立した評価

公開資産のgold利用履歴は監査して記録する。公開重みを競技用推論候補として検討することと、本リポジトリでgoldを学習・checkpoint選択に使うことは区別する。後者の禁止は維持する。ラベル作成、prompt、混合係数の調整にもgoldを使わない。

| 経路 | 許容する評価の呼び方 | 選択の根拠 |
|---|---|---|
| 公開競技重みの推論・追加学習 | 公開方式の再現、競技候補の比較。既存train上は露出あり／不明の診断 | 事前に固定した候補、実行契約、少数のPublic比較 |
| 検証対象を見ていない汎用初期重みからのfold学習 | groupを保ったweak検証。患者独立性は未確認 | 事前固定したweak指標、別foldでの再確認 |
| 公開重みを教師にする蒸留・pseudo-label | 教師の学習対象と選択履歴を継承した診断 | 教師の露出を監査するまで独立OOFとして使わない |

公開重みが全weak検査を学習済みなら、後から5分割しても、encoderを凍結しても、検証対象への露出は消えない。fine-tuningのローカルweak改善を独立した改善証拠にせず、fold別の未露出重みがない場合は、まず固定推論比較を優先する。58件goldは過去に監査値を見ており、完全未観測の最終テストとも呼ばない。

公開モデルがgoldを使った可能性だけで競技候補から一律除外しない。一方、個々の重み・コード・初期化モデルの条件は引き継ぐ。一括Datasetの表示ライセンスだけで全内包物の再配布を許可されたとは解釈しない。まずKaggleの元Inputを参照する構成とし、第三者重みの自作bundleへの再配布は独立して判断する。[公式Code Requirements](https://www.kaggle.com/competitions/rsna-knee-abnormality-detection/overview)、[10月4日のRules・Host本文監査](kaggle-source-eligibility-20261004.json)。

## 段階1：成功済みの比較基準を固定する

p001とr001について、submission ref、提出日時、global scriptVersionId、Notebook表示版、提出ファイル、スコアの証拠段階を記録する。コードは成功版を保存し、元ファイルとcode cellのSHA-256を残す。Inputは名前、種類、版、使うファイル名、取得できる場合は内容hash、利用条件を記録する。

**固定できなかった値はnullのまま理由を残す。** APIの現在版を提出時の版へ転記しない。Notebookへ継承されたmetadataのInput IDと現在のInput一覧を順序で結び付けない。コードの固定、資産の固定、数値再現、採点成功を別の完了条件にする。p001の保存資産が不完全でも、既存採点済み提出を保持したまま段階2の準備を進められる。理由のない再提出は行わない。

## 段階2：公開候補を一つ比較する

**最初の候補p002はDINOsaur V4のNotebook V32、最終`submission.csv`とする。** 10月4日に保存したソースを再取得し、SHA-256一致を確認できた。歴史的Input版と作者が採点したCSVは未確定なので、作者0.937の厳密再現を約束せず、固定した構成の自己採点候補として準備する。[候補比較の調査記録](public-candidate-review-20261005.json)。

NTejasの公開0.940/0.941は作者報告として確認した。保存参照Notebookと現在Kaggle版の23 code cellは一致する一方、metadataのID・GPU/Input情報が整合せず、採点された版を確定できない。末尾receiptの混合比と実コードにも不一致があり、CoAt/D4の失敗後に処理を続ける経路もある。高い表示値だけで最優先へ繰り上げず、今回は設計の参考候補に留める。[作者リポジトリの固定commit](https://github.com/NTejas-1/RSNA-Knee-Abnormality-Detection/tree/1c386ac71385ba7683f550b87a465386ba6c36a8)。DINOsaurにも分岐失敗時の継続があるため、全memberの完走確認は必須である。作者報告0.937/0.940/0.941は自己再現欄へ入れない。

1. 元Notebookのソース、全member、係数、TTA、前処理を一つの候補として固定する。最新版への追従、独自移植、r001混合を同時に行わない。
2. 必要Inputの版とファイル、offline wheel、モデルの初期化時通信、前処理失敗時のfallback、最終CSVを書き換えるセルを静的に調べる。
3. 候補ごとに新しいprivate Notebookを使い、元InputをAttachする。欠けたmemberを飛ばして形式だけ正常なCSVを出す場合、意図した候補の成功と扱わない。member完走のreceiptと最終ファイルを確認する。
4. GPU・Internet OFFで保存実行し、例示testの行・列・有限値・UID対応と完走を確認した後、手動で一度採点する。例示3検査の時間を隠しtestへ単純比例しない。
5. Public、隠しtest全体時間、Notebook/Input版、提出ファイルを記録する。0.924を上回り、必要memberが完走して時間に余裕があれば競技用の暫定主力へ進める。Publicでの優位をPrivate改善の保証とはしない。下回る、同点で重い、分岐が欠ける場合はp001を維持する。

歴史的Inputが復元できない場合、現在利用できる版を明示固定した「新しい組合せ」として扱う。元の0.940等の厳密再現を名乗らず、その組合せの実測を取る。未解決資産を抱えて候補を増やし続けず、一つを実行可能にする。今回の作業はコード・metadata・計画の準備までで、実行済みとはしない。

## 段階3：公開方式の専用経路と互換cacheを作る

採用候補の数値再現を先に作る。公開コードを既存`KneeMIL`へ押し込まず、専用の前処理・model・checkpoint読込み経路を分ける。既存のUID／提出列検査、hash、出所記録、欠損mask、group分割は再利用する。汎用の実験基盤と192px画素cacheの互換性を同一視しない。

最初はKaggleの元DICOMに対して、元Notebookと移植版を同じ学習側24〜32検査で比較する。goldおよびその連結groupはQCから除く。検査選択はラベル性能に基づかず、系列数、スライス数、方向、PixelSpacing、圧縮方式などを網羅し、private manifestで固定する。この実行は次工程であり今回は行わない。

| 検査箇所 | 合格条件 |
|---|---|
| 選択series・順序・crop・slice/window index | 元Notebookと一致。欠損系列・境界paddingも含む |
| uint8スタックとmask | 同一処理環境ではshape/dtype/全要素が一致 |
| モデル入力tensor | 正規化・チャネル順・resize補間・解像度を一致させる |
| 所見順・各member・最終予測 | 12列を名前で照合。元方式反復の数値揺れを先に測り、比較前に許容誤差を固定 |
| Kaggle最終出力 | 全member、正しい最終CSV、Report不要、通信不要、時間余裕を確認 |

許容誤差を結果に合わせて拡大しない。FP32/AMP、CUDA演算、ensembleのrank同順位などを別々に切り分ける。人工入力のforwardは実装契約の検査であり、実MRIの前処理同値性の代わりにはならない。

192pxの拡大から336/384px相当の細部や物理寸法は復元できない。元DICOMはKaggleで処理し、採用モデル仕様の新しいcacheを作る。CoAtNet単体の64×336×336×uint8を4,407検査に保存すると配列だけで31,842,091,008 bytes（約31.84GB／29.66GiB）。これは圧縮実測・最大RAM・全ensemble容量ではない。現在の18GB出力ガードを単に引き上げず、少数QCで計測し、容量に応じてshard化する。UID集合の重複・欠落、shardごとのhashと共通前処理版を検査する。重複3枚窓を全保存するよりスタックから窓を生成できるかを検討するが、元方式との一致を優先する。

## 段階4：改善は一つの仮説から始める

学習完全再現、公開重みからのfine-tuning、新しい教師によるfold学習は別実験にする。作者のsoft labelが未配布であることは学習完全再現の制約であり、公開重みの推論比較を止める理由ではない。soft labelの値を校正済み確率とは仮定しない。

| 実験 | 固定するもの／変更するもの | 採用条件 | 中止・保留条件 |
|---|---|---|---|
| 公開方式そのままの比較 | 版と全推論recipeを固定。方式全体をp001と比較 | 自己Publicと実行契約、時間余裕で判断 | 必須資産不足、利用条件未解決、member欠落、0.924以下 |
| 同じ公開方式の推論設定比較 | 重み・入力処理を固定し、仕様に適合する設定一つだけ変更 | 事前仮説と実測が整合し、追加コストに見合う | SWA/TTA等の一般論だけで試す、同時変更、Public係数探索 |
| 公開重みのfine-tuning | 元重みを保存し、教師・更新範囲・学習率等の変更を一つに限定 | 検証への露出を明示し、競技改善と独立評価を区別 | 既知train上のweak改善だけで採用、gold選択、広い探索 |
| ラベルの比較 | 入力・model・fold・seed・選択規則を固定、教師だけ変更 | P/N/未言及/不確実の意味とmaskを監査、別foldも確認 | 欠損の0埋め、goldからprompt調整、件数差だけで説明 |
| r001系による補完 | 主力と混合規則を事前固定。まず少数の根拠ある候補だけ | 主力単体より実測で改善し時間内に完走 | 低相関だけを根拠に採用、無根拠な50:50、所見係数の総当り |

再学習の優先順位は、公開主力の不足を示す診断と検証可能性がある場合に上げる。現在のBN差だけでは公開CoAtNetの弱点を補う証拠にならない。独立した画像検証が無い状況では、原因を断定した大量fine-tuningより、固定公開候補の少数比較を優先する。

各runには仮説、比較元、変更点、config、seed/fold、入力hash、環境、選択規則、予算、採用条件、中止条件、実測と理由を事前・事後で保存する。未実行の提案は実測台帳へcompletedとして追加しない。弱ラベルのmacro12 AUC、所見別AUC、観測・陽性・陰性・欠損数を確認し、少数陽性の補助指標を用いる場合もPublicと混同しない。
